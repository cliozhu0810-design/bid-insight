# 标鉴收费准备版

当前 GitHub Pages 是免费预览版。`billing-config.js` 固定为 `preview`，不会发起微信登录、付款或扣除正式试用次数。不要把浏览器标记、localStorage 或支付弹窗返回值当作付款凭据。

## 已准备

- UI：首次成功试用免费一次，此后人民币 5 元一次，每次 2–5 份标书；费用说明、微信登录入口、支付结果查询、开始分析前的数据提交确认。
- 服务端：公众号网页授权（snsapi_base）、HttpOnly 会话、服务端固定金额下单、RSA 支付请求签名、响应与回调验签、AES-GCM 回调解密、查单。
- SQLite 账本：按同一公众号下的 OpenID 记录一次试用；支付交易号唯一、通知幂等、用户订单隔离、任务唯一编号及材料摘要、失败保留次数、成功后扣除、进程重启恢复未完成任务。
- 正式分析接口：服务端 worker 完成比对，浏览器不能用“支付成功”或“分析成功”字段修改账本。前端重试同一任务时沿用内容摘要请求号；同请求号换内容会被拒绝。
- 公开预览的旧算法已经开源，不能阻止他人复制旧版自行运行；服务端收费保护的是正式服务，并非撤回已公开代码。

## 本地检查（不收款）

需要 Node.js 22.13 或以上，使用内置 SQLite，无 npm 第三方依赖。

```sh
npm test
npm start
```

打开 http://127.0.0.1:8980 。默认 `BILLING_ENABLED` 未设置，所有登录/支付/正式分析 API 返回“尚未开通”。数据库默认位于 `server/data/`，已加入 gitignore。禁止把数据库、密钥或真实账号资料提交到 GitHub。

## 正式启用的前置条件

本次没有真实公众号或商户号，未进行微信平台端到端联调，也没有启用收费后端。配置字段见仓库根目录 `.env.example`。由部署平台的密钥管理注入实际值，不要在聊天、源码或前端填写 AppSecret、API v3 密钥或私钥。

1. 准备具备网页授权权限的公众号、微信支付商户号、JSAPI 支付权限与 AppID 绑定。
2. 准备自己的已备案域名、HTTPS 和服务端持久化部署。GitHub Pages 不能运行此 Node 后端；当前 github.io 地址不是可直接开通本套正式支付的商户域名。
3. 本实现首先支持微信内置浏览器的公众号网页授权及 JSAPI 支付。电脑扫码登录需要另外接入微信开放平台网站应用；未实现。
4. 配置网页授权域名、JSAPI 支付目录、公众号 IP 白名单（如适用）、回调地址 `/api/payments/wechat/notify`，确认公众号 OpenID、下单 AppID、支付调起 AppID 一致。
5. 使用微信支付公钥模式，配置可信公钥 ID 及公钥文件；商户签名私钥与证书序列号单独配置。建立密钥轮换与微信支付公钥轮换流程。未知公钥 ID 会拒绝验签，不自动信任网络返回的密钥。
6. 上线前完成真实测试：登录、首用、重新登录/换设备、付款取消、重复点击、真实成功支付、回调丢失后查单、失败不扣次数、并发请求、重启恢复。补齐订单关闭/过期、退款与账单核对流程，以及运营主体、客服和退款说明后，才启用正式收费。本准备版尚未实现自动退款和完整运营对账。
7. 保留持久化数据库并定期备份，丢库会丢失试用/购买记录。本版本限单个 Node 进程、单副本运行；多实例部署需先改为共享数据库和任务租约，不能直接扩容多个副本。

在以上验收完成前保持 `BILLING_ENABLED=false`。正式环境由反向代理提供 HTTPS，代理至 Node 服务；默认只监听 127.0.0.1。`PUBLIC_ORIGIN` 必须为实际同源网站地址。

## 收费语义与数据

5 元购买一次成功分析的次数，不是会员或自动续费。试用或付费次数都只在服务器成功计算后扣除。支付成功但分析失败时，保留可用次数供重试，不会自动退回微信资金。重复提交同一请求和相同内容不重复扣次。

原始 PDF/DOCX/TXT、图片原图留在浏览器。正式分析经过用户确认后提交提取文字、候选字段及图片指纹；文字/比对结果在内存中处理，不写入计费数据库。数据库保存微信 OpenID、试用标记、订单、任务摘要与状态，不保存标书正文。服务器及反向代理应禁止记录授权 code、Cookie、支付密钥和请求体。

单次原始文件限制仍为 200 MB，最多 5 份；正式 API 的已提取 JSON 限制为 20 MB、正文 1,000 万字符、单文档最多 1,000 个页/段落。计算并发上限 2、每任务 120 秒超时；超限或超时不扣次数。需要更大处理能力时，应先压测并调整后端资源与限额。
